# Central-Procesing-Unit

## Introduction

The purpose of this lab is to design a simple central processing unit, more specifically known as a CPU, using VHDL to code the components and implement it into the FPGA board. The central processing unit consists of several components that work together. The main components consist of an ALU and a control unit, with secondary components including registers, seven-segment displays, and the control unit's contents. The control unit contains an FSM and a 3-8 decoder, allowing the control unit to operate as intended. The ALU processes data operations, while the control unit controls all of the units and operations of the CPU. The ALU processes 8-bit values received from two registers and operates on the provided values. The operation used by the ALU is controlled by the 3-8 decoder’s output. Once the operation is completed, the ALU outputs it to the seven-segment displays, which display the result on the FPGA board.

## Components

### Registers

Registers, also known as latches, were used as storage units which would temporarily store input values and send them to the ALU. In this case, the latches used were two D-latches, which contain two to three inputs and one output. D-latches always have a Clock and D input, and in this case, a reset input as well. When the Clock is active, the Q (Output) is equal to the value of D, and when the Clock is inactive, the Q (Output) remains the same. However,  when the Reset is active, all binary bits of Q are reset to zero.

### 3:8 Decoder

The 3:8 Decoder, in simple terms, converts 3-bit binary inputs into an 8-bit binary output with one bit set to high (1) and the rest set to low (0). For this lab in particular, a 3:8 Decoder was used to control the operation of the ALU. However, a 4:16 would be needed if there were 9 functions instead of 8. In this lab, the 3:8 Decoder received a 3-bit binary value from the FSM, given which state it was, and the decoder would convert it into an 8-bit binary value that the ALU could read and utilize.

### Finite State Machine (FSM)

The finite state machine is a system that cycles through a finite number of states, which is used to cycle through the functions in the ALU.  In this case, there were 8 states used to cycle through 8 functions in the ALU. There are two different types of finite state machines, being the Mealy and Moore FSM. Mealy’s output is dependent on the state and the data in values, while Moore’s output is dependent only on the just the state. In this lab, the Moore finite state machine was used.

## ALU1

ALU1's purpose was to have the ALU core perform eight different logical and arithmetic operations between the 8-bit binary values from Register A and Register B. The operations performed are the following: addition of A and B, subtraction of A from B, inversion of A, NAND, NOR, AND, XOR, and the OR of A and B. These functions are based on the set ‘OpCodes’, ranging from 00000001 to 10000000. These ‘OpCodes’ are cycled through by the decoder, which converts the FSM’s outputs into 8-bit binary numbers.

Block Diagram - ALU1 Block Schematic File 

![image](https://github.com/user-attachments/assets/5a709c3d-4771-4e4f-8b73-c9852742cc40)

### Inputs

The ALU inputs follow: ‘clk’ (clock), reset, Reg1, Reg2 and opcode. The clock activates the ALU when the clock changes from 0 to 1 (Positive Edge-Trigger). The reset input sets the ALU to its initial value (0) when it is 1. Reg1 and Reg2 are the two 8-bit binary values from the register1 and register2. Lastly, the opcode is provided by the decoder and decides which function is to be used.

### Outputs

The ALU outputs follow: result1, result2, result, neg, sum. Result 1 is the first 4 digits of the result and result 2 is the last 4 digits of the result. The result is the output from the function. The neg is a single-bit binary value that's ‘1’ when the result is negative and ‘0’ when it’s positive. The sum is a placeholder value used to calculate whether the result is negative or positive.

## ALU3

ALU3 only required one Latch, though we kept the second latch since the task given was very different from the previous one. The single function this time utilizes an 8-bit binary value to verify if one of A's two digits exceeds the student ID. It is flipped by the FSM if one of the two digits of A is greater than the student ID, then it displays ‘y’ on the modified seven-segment display, otherwise, it displays ‘n’.

Block Diagram - ALU3 Block Schematic File  

![image](https://github.com/user-attachments/assets/32304a69-e95c-4ed7-a0c4-7523220b2904)

### Inputs 

The ALU inputs follow: ‘clk’ (clock), reset, Reg1, Reg2, Student_Id and opcode. The clock activates the ALU when the clock changes from 0 to 1 (Positive Edge-Trigger). The reset input sets the ALU to its initial value (0) when it is 1. Reg1 and Reg2 are the two 8-bit binary values from the register1 and register2. The Student_Id is a 4-bit binary value which is from the FSM, which is cycled through every time the FSM is clocked. Lastly, the opcode is provided by the decoder and decides which function is to be used.

### Outputs

The ALU outputs follow: result. Result is the only output this time and it's a 4-bit binary value instead of an 8-bit binary value. Result is equal to ‘1111’ if ‘Y’ and ‘0000’ if ‘N’.
